# Проверка Firestore Rules в Emulator

Дата: 6 ноября 2026. Результат: **12/12 интеграционных тестов и 21/21 прежних тестов пройдены**.

Проверено официальным Cloud Firestore Emulator 1.22.0, Firebase CLI 15.35.0, Firebase Web SDK 12.4.0 (тот же, что в firebase-init.mjs), @firebase/rules-unit-testing 5.0.0, Java 25.0.3. Правила успешно загружены и скомпилированы эмулятором. Запуск завершился с кодом 0, эмулятор остановлен.

## Согласованность

Несовместимостей не обнаружено. firestore.rules и cloud-store.mjs в рамках этой проверки не менялись. Интерфейс не менялся. В рабочую базу не отправлялись запросы, правила не публиковались.

- Единственное место создания запросов подписки в cloud-store.mjs всегда создаёт `query(collection(..., 'marks'), limit(4))`. Тест использует сам createCloudStore и настоящий SDK, загружает четыре записи для каждого из 14 дней и получает все 56 записей. Тем самым проверены и разрешение правил, и отсутствие случайного меньшего лимита.
- Транзакция читает отсутствующий документ через разрешённый get, затем выполняет create с реальным serverTimestamp. У существующего документа выполняется delete. Ветки update нет.
- Снятие и повторное добавление через настоящий адаптер проходят правила и перемещают имя в конец; обрабатываются серверные seconds/nanoseconds.
- Одновременные транзакции двух SDK-клиентов сохраняют отметки разных участников. При переключении одного участника конфликт повторяется SDK как create/delete, без запрещённого update.

Все проверяемые операции выполняются неавторизованными SDK-клиентами под настоящими правилами. Обход правил используется только для подготовки отдельных фикстур (например, прошедших или заведомо некорректных документов); проверяемые get/list/create/update/delete его не используют. Логи PERMISSION_DENIED в отрицательных тестах ожидаемы.

## Повторный запуск

Нужны Node.js с npm и Java 21 или новее в PATH. На этой машине Java найдена в Android Studio; в PowerShell при необходимости:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
npm ci
npm run test:rules
npm test
```

Если npm отсутствует, здесь использовался официальный npm, локально загруженный в игнорируемую .tools/npm; эквивалент: `node .tools/npm/package/bin/npm-cli.js run test:rules`. Для повторного использования скачанного jar можно задать `$env:FIREBASE_EMULATORS_PATH = Join-Path (Get-Location) '.tools\emulators'`.

Команда test:rules использует только firebase.emulator.json, проект demo-gooffice-rules и адрес 127.0.0.1:8085. Тест останавливается до любых запросов, если FIRESTORE_EMULATOR_HOST не равен этому адресу. production-конфигурация приложения не импортируется. Вход в Firebase не требуется. Данные эмулятора очищаются перед каждым тестом и не экспортируются.

Зависимости package.json нужны только для проверок; сайт по-прежнему работает без сборки и без npm в браузере. package-lock.json фиксирует версии. Эмулятор не проверяет опубликованное состояние production-правил, настройки App Check и ограничения API key. Саму публикацию выполняет пользователь отдельно.
