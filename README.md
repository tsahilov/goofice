# В офис

Локальный прототип календаря для пяти участников. HTML, CSS и JavaScript без зависимостей, установки пакетов и сборки. Правила и план — в [SPEC.md](./SPEC.md).

## Как посмотреть

Откройте `index.html` двойным щелчком. Календарь работает без сервера и доступа к интернету.

Для проверки синхронизации между вкладками рекомендуется единый локальный адрес. Если установлен Node.js, из папки проекта выполните:

```powershell
node tools/preview.cjs
```

Затем откройте http://127.0.0.1:4173 в двух вкладках одного браузера. Для остановки предпросмотра нажмите `Ctrl+C` в терминале. Это вспомогательный статический предпросмотр; у самого приложения нет серверной части.

## Что проверить

1. Откройте страницу: видны текущая и следующая недели, выбор имени не требуется.
2. Нажмите любой статус. Выберите одно из пяти имён: исходное нажатие сразу применяется.
3. Нажмите другой статус — он заменит предыдущий. Повторное нажатие снимет отметку.
4. Выберите другое имя в шапке и измените его отметку. Отметки остальных останутся на месте.
5. Обновите страницу: имя и отметки сохранятся.
6. Откройте второй экземпляр по тому же локальному адресу. Измените отметку в одной вкладке и проверьте другую. Выбранное имя в уже открытой вкладке остаётся прежним.
7. Проверьте узкое окно: недели показываются списком, все переключатели доступны касанием. Выходные редактируются так же, как будни.
8. Закройте выбор имени крестиком, по фону или клавишей `Esc`: отметки не изменятся. Кнопки доступны с клавиатуры через `Tab` и `Enter` / пробел.

Тестовые данные создаются один раз для двух недель первого запуска. Отсутствие отметки — отсутствие записи, пустые группы не выводятся. После смены недели прошлые даты удаляются, отметки общей недели сохраняются. Новые даты сначала пустые.

## Локальная проверка

Нужен Node.js 18 или новее. Проверки не требуют установки пакетов:

```powershell
node --check data.js
node --check app.js
node --test tests/project.test.cjs
```

Проверяются границы недель, месяцев и лет, високосный февраль, переходы часовых поясов, выбор и снятие статусов, сохранение имени, синхронизация данных, удаление прошедшей недели и работа при недоступном localStorage.

Результат проверки первого этапа: все 10 автоматических проверок пройдены. В браузере проверены первое редактирование, отмена выбора имени, замена и снятие отметки, сохранение после перезагрузки, смена участника, обмен отметками между двумя вкладками и экраны шириной 320 и 390 пикселей. Ошибок в консоли нет. Снимки интерфейса: [широкий экран](./preview/desktop.jpg), [мобильный экран](./preview/mobile.jpg).

## Файлы

- `index.html`, `styles.css` — разметка и адаптивное оформление.
- `data.js` — пять участников, статусы, даты и локальное тестовое хранилище.
- `app.js` — отображение и взаимодействия.
- `tests/project.test.cjs` — проверки календаря и хранилища стандартными средствами Node.js.
- `tools/preview.cjs` — необязательный локальный предпросмотр.

Имена меняются в массиве `MEMBERS` в `data.js`. Значения `id` лучше сохранять, чтобы не потерять связанные тестовые отметки.

## Ограничение первого этапа

localStorage объединяет вкладки только одного браузера на одном адресе; между устройствами данные не передаются. При открытии через `file://` поведение хранения зависит от браузера. Если хранение недоступно, интерфейс работает в памяти до перезагрузки и сообщает об этом внизу страницы.

Firebase и публикация пока не подключены. Для будущей публикации на GitHub Pages готовы четыре статических файла (`index.html`, `styles.css`, `data.js`, `app.js`) с относительными ссылками. На следующем этапе тестовое хранилище будет заменено на Firestore.
