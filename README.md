# gooffice

Календарь двух недель для команды, HTML/CSS/JavaScript без сборщика. Общие отметки и список до 20 участников — Cloud Firestore, выбранный профиль — localStorage. Внешний Firebase Web SDK загружается браузерными ES-модулями, обычное и курсивное начертания Medeo Sans остаются локальными.

Запуск: `node tools/preview.cjs`, затем http://127.0.0.1:4173. Открытие через file:// не поддерживается.

Инструкция Firebase Console, схема, тесты и ограничения: [FIRESTORE.md](./FIRESTORE.md). Правила: [firestore.rules](./firestore.rules). Их необходимо проверить и опубликовать вручную; автоматически ничего не применяется.

Динамические участники, безопасная миграция, порядок публикации и ручное удаление: [PARTICIPANTS.md](PARTICIPANTS.md). Сначала вручную обновляются совместимые правила, затем инициализируется реестр исходных четырёх профилей, затем публикуется новый сайт. В рамках разработки рабочая база и опубликованный сайт не изменялись.

Проверка: `npm test` — 27 проверок; `npm run test:rules` — 26 проверок в настоящем Firestore Emulator. Подробности: [tests/PARTICIPANTS-RESULTS.md](tests/PARTICIPANTS-RESULTS.md).

Старое локальное тестовое хранилище оставлено как тестовый адаптер в data.js; приложение его больше не использует и отметки из него не переносит. Реестр реализован в participants.mjs, отметки — в cloud-store.mjs. Добавление участника доступно через поле «Вписать своё имя» в шапке.

Для проверки самих правил: `npm ci`, затем `npm run test:rules` (нужна Java 21+). Это зависимости разработки, сборка сайта не добавлена. Команда запускает официальный Firestore Emulator с проектом demo-gooffice-rules. Прежний протокол для четырёх фиксированных участников сохранён в tests/FIRESTORE-EMULATOR-RESULTS.md как исторический.

Визуальный слой находится в visual-effects.mjs; текущие настройки типографики, hover, подчёркивания и SVG-контура сохранены. Исторический протокол предыдущего этапа: [VISUAL-CHECKS.md](VISUAL-CHECKS.md).
