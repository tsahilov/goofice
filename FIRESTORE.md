# Firestore: подключение и ручная проверка

Текущая версия: действующий список участников хранится в `team/registry`, максимум 20. Миграция и порядок выпуска описаны в [PARTICIPANTS.md](PARTICIPANTS.md). Ниже описание первоначальной интеграции уточнено под новый реестр.

Интерфейс сохранён. `firebase-init.mjs` загружает Firebase Web SDK 12.4.0 браузерными ES-модулями и использует предоставленную конфигурацию. npm и сборка не нужны. `cloud-store.mjs` — новое общее хранилище; локальный адаптер в data.js оставлен только для прежних тестов, приложение его не вызывает.

## Запуск

В папке проекта выполните `node tools/preview.cjs`, откройте http://127.0.0.1:4173. Прямое открытие index.html через file:// больше не поддерживается из-за браузерных модулей. Нужен доступ к gstatic.com и Firestore. Запуск предпросмотра не публикует сайт.

## Модель

Путь: `days/YYYY-MM-DD/marks/memberId`. Допустимые ID берутся из профилей `team/registry`; до инициализации реестра разрешены исходные alan, denis, anya, dasha. Поля: memberId, dayStart (timestamp календарной даты в UTC-полночь как числового представления даты), createdAt (serverTimestamp). День офиса определяется в Europe/Moscow.

Один путь на пару исключает дубликаты. Транзакция читает документ и создаёт либо удаляет его. Разные участники не перезаписывают общий массив. Порядок — seconds, затем nanoseconds серверного createdAt, затем ID документа. После удаления и повторного создания новая серверная метка ставит человека в конец. При действительно одновременных добавлениях порядок совпавших времён определяется ID.

14 независимых onSnapshot-подписок читают по одному дню с where(documentId(), in, currentIds) и limit(20). При изменении реестра запросы пересоздаются. При смене недели старые подписки снимаются. Неподтверждённые локальные снимки не применяются. Успех объявляется только после подтверждения транзакции. Ошибка записи сохраняет прежний подтверждённый вид и выводит сообщение; повторное нажатие — явная повторная попытка. Офлайн-записи не ставятся в очередь. При ошибке подписки требуется обновление страницы. Последний подтверждённый вид может оставаться видимым при разрыве связи; индикатор соединения зависит от сообщений SDK и не является мгновенной проверкой доступности сервера.

localStorage используется только для выбранного имени (прежний ключ gooffice.demo.v2.member). Тестовые отметки не читаются и не отправляются в облако. Они остаются в браузере. Старые документы Firestore автоматически не удаляются: скрываются периодом календаря; очистка/TTL — отдельный этап.

## Действия в Firebase Console

1. Откройте https://console.firebase.google.com/ и выберите gooffice-5f6c0.
2. Откройте Build → Firestore Database. Убедитесь, что используется база `(default)`.
3. Перейдите в Rules. Скопируйте текущие правила в резервный файл.
4. Вставьте целиком содержимое firestore.rules вместо прежних правил. Не оставляйте рядом глобальные разрешающие правила: разрешения суммируются.
5. До публикации проверьте синтаксис редактором и Rules Playground. Для unauthenticated get пути days/<сегодня в Москве>/marks/alan чтение должно разрешаться. Get чужой коллекции и отсутствующего в реестре участника — отклоняться. Create с memberId alan, dayStart соответствующим дате и createdAt равным времени запроса — разрешаться; с дополнительным полем, неверным участником, прошлой датой или произвольным createdAt — отклоняться. Update всегда запрещён. Delete сегодняшней корректной записи разрешён, прошедшей — запрещён.
6. Playground не заменяет проверку реальной serverTimestamp-трансформации: произвольный timestamp из формы обычно не равен request.time. Успешную запись проверьте SDK из приложения после публикации правил. Правила уже проверены локально в официальном Firestore Emulator; результаты и повторный запуск — tests/PARTICIPANTS-RESULTS.md.
7. После успешной проверки нажмите Publish самостоятельно. Эти правила автоматически не применялись.
8. Обновите локальную страницу. Дождитесь исчезновения «Загрузка отметок…». Если permission-denied остаётся, проверьте проект, базу и опубликованные правила.
9. В двух браузерах/устройствах, открыв одну версию сайта, выберите разные имена. Добавьте отметки в разном порядке на будущую дату. Проверьте немедленное появление, одинаковый порядок, снятие и повторное добавление в конец, перезагрузку.
10. Отключите сеть и проверьте отсутствие ложного сообщения об успехе. После восстановления сети при необходимости обновите страницу. Никакие тестовые данные не должны появиться из старого localStorage.

Создавать родительские документы days и коллекции вручную не требуется; они появятся при первой успешной записи. Составной индекс не требуется.

## Ограничения безопасности

Без авторизации невозможно проверить, кто действительно Алан или Даша: любой, знающий проект, может читать разрешённые даты, создавать и удалять отметки любого допустимого участника, в том числе вне интерфейса. Firebase config и API key веб-приложения публичны и не заменяют правила. Эти правила ограничивают структуру, ID, время создания, число результатов запроса и временной диапазон, но не обеспечивают приватность команды и защиту от массовых запросов/расходов. App Check, квоты/бюджетные уведомления и авторизация — возможные отдельные меры; сейчас не подключены.

Правила допускают чтение от московского сегодня минус 6 дней до плюс 13 дней; запись — от сегодня до плюс 13 дней. Это ограниченный серверный защитный диапазон; точное окно понедельник–воскресенье двух недель дополнительно соблюдает клиент. Доступ к остальным путям запрещён. При одновременном переключении одной и той же отметки результат определяется повторными попытками транзакций, а не личностью инициатора.

## Проверки

- `npm test` — 27 календарных и локальная регрессия / проверка адаптера с подставным SDK.
- `npm run test:rules` — 26 интеграционных тестов в официальном Firestore Emulator: компиляция правил, настоящие onSnapshot-запросы, разрешённые/запрещённые операции и транзакции двух реальных SDK-клиентов.

В test:rules используются Firebase SDK 12.4.0, demo-проект и localhost; production-конфигурация не импортируется. Подробности и требования к Java/npm: [результаты проверки](tests/PARTICIPANTS-RESULTS.md). Изменения реестра и интерфейса проверялись локально. Реальные записи в общую базу не выполнялись, правила не публиковались.
